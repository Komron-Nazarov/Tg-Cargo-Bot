Ты работаешь с существующим проектом Cargo Bot на Python.

Это уже работающий минимальный Telegram-бот. Его нельзя переписывать с нуля без необходимости.

Основной стек:
- Python
- aiogram 3
- asyncpg
- PostgreSQL
- python-dotenv

Полная бизнес-спецификация находится в:

`docs/CARGO_MVP_SPEC.md`

Главная задача — постепенно превратить существующий бот в рабочий Cargo MVP для реального бизнеса по доставке грузов Китай → Таджикистан.

ВАЖНО:

1. Сначала полностью изучи существующий репозиторий.
2. Изучи `docs/CARGO_MVP_SPEC.md`.
3. Не изменяй код на первом этапе.
4. Определи:
   - что уже реализовано;
   - что можно сохранить;
   - что необходимо переработать;
   - что необходимо добавить;
   - какие архитектурные проблемы существуют;
   - какие изменения потребуются в PostgreSQL.
5. Не переписывай рабочий код только ради другой архитектуры.
6. Не реализуй функции, которых нет в MVP.
7. Не добавляй AI, marketplace, GPS, escrow и другие функции будущих версий.
8. Сохраняй существующий стек.
9. Все изменения БД должны быть контролируемыми и не должны случайно уничтожать существующие данные.
10. Не храни секреты в коде и не изменяй `.env` без необходимости.

После анализа покажи:

- текущую архитектуру;
- найденные проблемы;
- предлагаемую архитектуру;
- новую структуру проекта;
- необходимые таблицы PostgreSQL и связи;
- какие существующие файлы будут сохранены;
- какие будут изменены;
- какие будут созданы;
- roadmap реализации по небольшим этапам.

НЕ НАЧИНАЙ реализацию, пока не закончишь анализ.

Основной принцип:

сначала сохранить работающую систему → затем рефакторинг → затем новые функции → после каждого этапа запуск и проверка.

Конечный MVP должен поддерживать основной flow:

Клиент
→ регистрация
→ получение Client ID
→ получение адреса склада в Китае
→ добавление Chinese Tracking Number
→ поступление товара на китайский склад
→ определение клиента
→ создание Cargo ID
→ добавление фото, веса, объёма и количества мест
→ консолидация
→ отправка
→ транзит
→ прибытие в Таджикистан
→ таможня
→ Душанбе/Худжанд
→ пункт выдачи
→ получение клиентом
→ фиксация оплаты
→ завершение.

После анализа остановись и дождись подтверждения следующего этапа.
